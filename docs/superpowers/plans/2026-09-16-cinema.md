# Cinema (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Browse the films Jellyfin knows about and play them inside our own page, on the LAN, with the key never leaving Flask.

**Architecture:** Jellyfin owns the library and the transcoding. `backend/cinema/` is a translating proxy: a small client, a device profile, routes under `/api/cinema` that reshape listings, proxy images and bytes, and strip the API key out of HLS playlists. `frontend/src/cinema/` is a poster grid, a film page and a player that uses hls.js (native HLS on Safari).

**Tech Stack:** as before, plus `requests` (backend, pinned) and `hls.js` (frontend, pinned).

Spec: `docs/superpowers/specs/2026-09-16-cinema-design.md`. Read its "What Jellyfin actually does" section first; every task below depends on those facts.

---

## Order, and why

Task 3 ends with a film playing in the page. Everything after it is shape and polish. If Task 3 does not work, nothing later matters, so it comes first.

## Conventions carried over

- Backend tests stub the client the way music tests stub the database; integration tests are marked and deselected by default (`pytest.ini` gains `jellyfin`).
- Frontend: tests first, `vi.mock` for the API module, one test file per module. Suites must be green before each commit, with the exit code checked, not the tail of the output.
- The Jellyfin running locally (`brew`, port 8096, user `liv`) with three test films is the development target. `scratchpad/jellyfin.env` from the spec session has the current key; Task 1 replaces it with a script.

### Task 2: Play, stream and stop (backend)

**Files:** `cinema/profile.py`, `cinema/playlist.py`, `cinema/cinema.py` (play, file, videos, stop routes only), `app.py` (register), tests, fixtures.

- [ ] **Step 1: Record fixtures** from the live Jellyfin into `tests/fixtures/jellyfin/`: `items.json` (the three films with MediaSources), `playbackinfo_direct.json`, `playbackinfo_remux.json`, `playbackinfo_transcode.json`, `master.m3u8`, `main.m3u8`. Replace the real key in them with `REDACTED-KEY` before committing; the tests assert on that string.
- [ ] **Step 2: Failing tests, `test_cinema_profile.py`.** `playback_kind` returns `direct` for mp4+h264+aac, `remux` for mkv+h264+ac3, `transcode` for hevc, `transcode` for h264 in mkv with an audio codec we cannot play but a *video* profile we cannot copy (High 10), `direct` for webm+vp9+opus. The profile dict lists the four h264 profiles and level 51; a test asserts that, because dropping them silently costs a video transcode.
- [ ] **Step 3: Failing tests, `test_cinema_playlist.py`.** `strip_api_key` removes `ApiKey=...` whether it is first (`?ApiKey=x&a=1` → `?a=1`), middle, or last (`a=1&ApiKey=x` → `a=1`); leaves a playlist with no key byte-identical; leaves `#` comment lines alone; handles the recorded `master.m3u8` and `main.m3u8`, after which `'ApiKey' not in result`.
- [ ] **Step 4: Failing tests, `test_cinema_routes.py`** with the client stubbed on `cinema.cinema`:
  - `POST /api/cinema/films/<id>/play` with `{device_id}` → for the direct fixture `{kind: "direct", url: "/api/cinema/films/<id>/file", play_session_id}`; for the remux fixture `{kind: "hls", url: "/api/cinema/videos/<vid>/master.m3u8?<params>", play_session_id}` where the params are Jellyfin's minus `ApiKey`; the client was constructed with the given `device_id`; missing `device_id` → 400.
  - `GET /api/cinema/videos/<vid>/master.m3u8?...` → body has no `ApiKey`, `Content-Type` is `application/vnd.apple.mpegurl`, and the upstream was called with the same query string.
  - `GET /api/cinema/videos/<vid>/hls1/main/0.ts?...` → bytes pass through unchanged with upstream `Content-Type`.
  - `GET /api/cinema/films/<id>/file` with `Range: bytes=0-99` → upstream called with that Range; 206, `Content-Range`, `Accept-Ranges` and `Content-Type` copied from upstream.
  - `POST /api/cinema/play/<psid>/stop` with `{device_id}` → upstream `DELETE /Videos/ActiveEncodings?deviceId=..&playSessionId=..`; 204.
  - `JellyfinUnavailable` from any route → 503 JSON naming Jellyfin. This is the failure case that matters: a Jellyfin that is down must not take the site with it.
- [ ] **Step 5: Implement.** Proxy responses use `flask.Response(stream_with_context(upstream.iter_content(65536)))` for bytes; playlists are read whole, stripped, and returned with a recomputed length. Copy only `Content-Type`, `Content-Length`, `Content-Range`, `Accept-Ranges` from upstream; never `Set-Cookie` or `Access-Control-*`. Register the blueprint under `API_PREFIX` like the others.
- [ ] **Step 6: Prove it with curl** against the live Jellyfin, through Flask: play Paper Moon, fetch the master through `/api/cinema`, grep for `ApiKey` (must be absent), fetch a segment, stop. Then the HEVC film. Then the mp4 with a Range.
- [ ] **Step 7: Commit** — `feat(cinema): play, stream and stop through Flask`
