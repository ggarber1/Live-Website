# AWS and Login Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The whole site live at `https://livs.greggarber.net`, behind a login, on an EC2 instance in Greg's personal AWS account, in time for 27 September. The Pi is unreachable (home wifi down), so the "Pi in the cloud" replaces it for now; nothing here prevents moving back.

**Architecture:** One Ubuntu 24.04 EC2 instance is the Pi: MariaDB, gunicorn, Jellyfin and the media all on it, media on a separate EBS volume mounted at `/mnt/media`. Caddy in front terminates TLS for the domain and proxies to gunicorn on localhost. Flask gains a session login: one household password, a cookie, and every `/api` route behind it except login itself. Jellyfin stays on localhost, reached only through Flask, as the cinema spec already required. Provisioning is a script, run once over ssh.

**Tech Stack:** as before, plus Caddy. `werkzeug.security` for the password hash (already a dependency via Flask). AWS CLI with `--profile personal` for every call; the default profile is a dead work credential and is never used.

Spec context: `docs/superpowers/specs/2026-09-09-media-library-design.md` Phase 3 (the auth boundary and "Jellyfin behind the proxy" parts apply; Route 53 dynamic DNS and the CGNAT question do not, since an Elastic IP is static).

## Decisions

- **One password, not accounts.** Two people, one house. A `users` table is the spec's Phase 3 idea for public access to a Pi; here it is a `SITE_PASSWORD_HASH` in `.env` and a signed session cookie. Accounts can come later without changing the routes.
- **The guard is in Flask, not Caddy.** Caddy `forward_auth` would work, but Flask already fronts everything including Jellyfin, and a `before_request` hook is testable in the existing suite. Caddy does TLS and nothing else.
- **What is open without a login:** the SPA shell and its assets (so the login page can load), `POST /api/auth/login`, `GET /api/auth/me`. Everything else under `/api` answers 401 JSON. The frontend turns any 401 into a visit to `/login`.
- **Cookie:** `HttpOnly`, `SameSite=Lax`, `Secure` when `SITE_HTTPS=1` (set by provisioning), 30-day lifetime, refreshed on use. Lax plus JSON bodies is enough CSRF protection for this site: a cross-site form post cannot send JSON and a cross-site fetch does not carry a Lax cookie.
- **Login attempts are throttled** in memory: after 5 failures from one address, 30 seconds of 429. Enough against idle scanning; the password is the real defence.
- **Instance:** `t3.small` (2 vCPU, 2 GB) in `us-west-2`. Remux and direct play are fine; HEVC transcodes are not, same as the Pi, and `cinema-audit` still says which. Root volume 16 GB gp3; media volume gp3, size chosen by Greg (100 GB default). An Elastic IP so the DNS record never changes.
- **Security group:** 443 and 80 from anywhere (80 only so Caddy can redirect and answer ACME), 22 from Greg's current IP only.
- **Media gets there by rsync** from the Mac over ssh. Jellyfin's setup uses `scripts/jellyfin-dev.sh` through an ssh tunnel, exactly as locally.
- **Backups:** a nightly EBS snapshot of the media volume via Data Lifecycle Manager, 7 kept, and a nightly `mysqldump` to the media volume so the snapshot has the database too. Photos and captions are the irreplaceable part.

## Configuration added

| Variable | Meaning |
| --- | --- |
| `SECRET_KEY` | Signs the session cookie. Generated by provisioning. |
| `SITE_PASSWORD_HASH` | From `flask --app app hash-password`. Never the password itself. |
| `SITE_HTTPS` | `1` in production: sets the cookie's `Secure` flag. |

## Endpoints added, under `/api/auth`

| Method | Path | Does |
| --- | --- | --- |
| POST | `/login` | `{password}` → 204 and the cookie; 401 wrong; 429 throttled. |
| POST | `/logout` | Clears the cookie → 204. |
| GET | `/me` | `{authenticated: bool}`. Open, so the frontend can ask before rendering. |
